# wispr-fox UX/UI + code audit — 5 Jul 2026

Basis: v2.0.0 stable, the 17 screenshots in `Foxy screenshots_ 5 Jul 2026/`,
and a full read of the frontend routes + targeted Rust checks.
Audience/value-prop lens: PM/tech/business folks who want a clean, easy,
**free** Whisper-Flow alternative. Nothing here has been changed yet —
this is the review-before-implementation list.

---

## A. Bugs / factual inconsistencies (fix regardless of design taste)

### A1. Version mismatch — updater permanently says "Update available — v2.0.0 (you're on v1.4.0)"
`src-tauri/Cargo.toml` still says `version = "1.4.0"` while `tauri.conf.json`
and `package.json` say `2.0.0`. The update check (`commands.rs:564`) uses
`env!("CARGO_PKG_VERSION")`, so every v2.0.0 user sees a phantom update
banner in Settings → General forever. The sidebar (which uses `getVersion()`
from tauri.conf.json) says v2.0.0 at the same time.
**Fix:** bump Cargo.toml to 2.0.0 and add a release-checklist note (or derive
one from the other in CI).

### A2. Security page contradicts itself: "Keyring verified" + every key "Encrypted fallback"
Screenshot shows the green "Keyring verified" pill while all 5 saved keys sit
in the DPAPI encrypted-fallback file. If the keyring verifies now, saved keys
should be migrated into it on read (CLAUDE.md says opportunistic migration is
the design). Either the migration isn't running for encrypted-fallback
entries, or the pill copy is misleading. A security-curious user reads this
as "something is wrong."
**Fix:** migrate `.keys.enc.json` entries into the keyring when
`keyring_works`, or reword the pill/row so the state reads as intentional
("Keyring available — keys pending migration" → button to migrate now).

### A3. Draft's "LLM cleanup" toggle silently breaks Draft mode
Settings → Modes gives Draft (and Advanced) an "LLM cleanup" checkbox.
`flow.rs:973` — with it off, F9 returns the **raw transcript**: Draft mode
stops drafting entirely, with no warning. For Transcribe the toggle is the
feature; for Draft it's a foot-gun.
**Fix:** remove the toggle for Draft (and Advanced), or replace with copy +
confirm ("turning this off makes Draft behave like Transcribe").

### A4. Onboarding hardcodes Windows copy
Setup step 2: "Stored on your machine only (Windows Credential Manager)" —
shown on macOS too. `prettyHotkey()` already handles per-platform keys; the
storage line should say Keychain on Mac.

### A5. "Usage today" mixes daily and lifetime numbers
Sidebar footer is titled "USAGE TODAY … resets at 05:30 am", but when
Deepgram is selected the STT line shows **cumulative** credit spend
($2.32/$200 lifetime). Only a hover tooltip admits this. Also the bar
denominators (2,000 STT calls / 1,000 LLM calls / 200k tokens / 3600s audio)
are Groq free-tier numbers applied to every provider.
**Fix:** label the Deepgram line "credit used" (not under "today"), and make
denominators provider-aware or drop the % fill where it's meaningless.

### A6. Onboarding "resets every midnight" is UTC midnight
For the IST user that's 05:30 — the sidebar gets this right, the onboarding
copy doesn't. Minor: say "resets daily (midnight UTC)".

## B. The one big UX problem: four vocabularies for three modes

The same three modes are named differently in five places:

| Surface | Names used |
|---|---|
| Onboarding cards | **Raw / Cleaned / Drafted** |
| Sidebar hotkey box | **Light / Draft** |
| Settings → Modes | **Transcribe / Draft / Advanced (legacy)** |
| Settings → Dictation | **Transcribe / Transcribe + force-clean / Draft / Advanced cleanup** |
| History filter pills | **All / Light / Advanced / Drafting / Errors** |
| History row tabs | **Raw / Cleaned / Drafted** |

A new user who learns "Raw/Cleaned/Drafted" in onboarding then meets
"Light" and "Drafting" in History and "Transcribe" in Settings. This is the
single highest-leverage unification.

**Proposal:** one canonical pair of user-facing mode names —
**Transcribe** (F8) and **Draft** (F9) — used everywhere a *mode* is meant;
keep **Raw / Cleaned / Drafted** only for the three *text versions* inside a
history row (that distinction is real: one recording can have all three).
Concretely: sidebar "Light→Transcribe"; History pills "Light→Transcribe",
"Drafting→Draft"; onboarding card titles become "Transcribe (raw)",
"Transcribe (cleaned)", "Draft". "Advanced (legacy)" disappears from the
History filter (fold into an overflow or drop) and stays only as the
collapsed legacy block in Settings.

## C. Redundancy / information architecture

### C1. The sidebar is doing Settings' job
Expanded sidebar stacks: brand, nav, Dictation-keys card, Models panel
(2 provider + 2 model dropdowns + Clean toggle + Keys link), 9-icon avatar
grid + S/M/L, Replay onboarding, hero fox, Usage-today block. That's a
settings page pinned to every screen. Model/avatar switching is a
once-a-week action, not an every-glance need.
**Proposal (discuss):** keep sidebar = nav + hotkey reminder + usage + fox.
Move Models into Settings only (it already exists there — full duplication),
and collapse the avatar grid to a single current-avatar chip that links to
Settings → Appearance. If quick switching matters, a compact popover from
that chip preserves it without permanent pixels. Frees ~300px of vertical
space and makes the app feel calm instead of dense.

### C2. Avatar is configurable in three places
Sidebar grid, Settings → Appearance tiles, and the floater right-click menu.
Three sources of truth for skin + size. Keep the context menu (it's at the
point of use) + Settings; drop or reduce the sidebar one (see C1).

### C3. "Replay onboarding" appears twice in the markup
`+layout.svelte` renders it (and the hero fox) in both `.sidebar-top` and
`.sidebar-bottom`; the bottom pair is hidden by CSS (`display:none`). Dead
markup — delete the bottom copy. The code comment also says it's a dev-mode
helper with a TODO to hide it; decide: keep for users (it's genuinely useful)
but style it as a quiet footer link, or gate it.

### C4. Cross-references between settings pages are heavy and drifting
Every settings page ends with a dashed "tip" box pointing at 2–3 other pages
("hotkeys live in Dictation, prompts in Modes, keys in Security…"). Modes'
tip references **"Settings → Providers & Models"** — a page that doesn't
exist (it's "Providers", titled "Providers & API keys"). The tips exist
because the split itself is confusing (see C5). Trim to at most one pointer
per page, with correct names.

### C5. Settings section names don't match their content
- Nav says **"Avatar"** → page is titled **"Appearance"** (and contains
  Theme + window behaviour, so Appearance is right; rename the nav item).
- Nav letter-icons `K M D A G !` look like keyboard shortcuts but aren't
  (K = Providers?). Replace with small SVG glyphs like the main nav, or drop
  the icons entirely.
- **General** contains Startup, Audio cues, **Data retention, Updates** but
  its lede says only "Startup behaviour and audio cues". Retention/Updates
  deserve either their own "Data & updates" section (there's already a
  `/settings/data` route stub redirecting to general!) or the lede should
  be honest.

### C6. Home = History works, but the header stack is tall
Stats strip + title row + search + filter row = four bands of chrome before
the first transcript. Fine on a big monitor, cramped on a 13" laptop. Cheap
win: merge the count/refresh/folder controls into the search row, and let
the stats strip collapse to one line (it's already a link to /stats where
everything repeats).

## D. Copy / tone (2026-polish pass)

- **Too many words everywhere.** Settings paragraphs run 2–3 lines where one
  clause would do (e.g. Modes' Transcribe description is 45 words + a
  Shift+F8 aside; the macOS a11y banner is a 60-word paragraph). Recommend a
  global pass: every lede ≤ 1 sentence, every checkbox explanation ≤ 1 line,
  details into tooltips/`<details>`.
- "Advanced (legacy)" — the word "legacy" is dev-speak in user UI. If it
  must stay, "Cleanup only (optional)".
- Theme card says "(Retro warm theme is in progress — placeholder for now.)"
  but `app.css` has a complete retro palette that works. Delete the
  parenthetical (or the theme, but it works).
- "Hold to clear all" button is permanently visible danger-red in the History
  toolbar. Move behind the ⋮/Folder cluster or an overflow menu — destructive
  actions shouldn't be a first-class always-on button.
- Mixed persona: onboarding is "Hi, I'm Foxy", the rest of the app never
  mentions Foxy again (title bar/brand: wispr-fox). Decide: Foxy is the
  mascot's name, wispr-fox the product — fine, but one line in onboarding
  ("Foxy" = the fox that sits on your screen) would tie it.
- Save-hotkeys flow: button + "changes take effect after restarting
  wispr-fox" — restart-to-apply is a papercut worth fixing eventually
  (re-register shortcuts live); until then put the restart warning **on** the
  toast, not in small print under the button.

## E. Visual design read (designer's POV, from the screenshots)

Honest overall: **7/10 — cohesive and characterful, dense and slightly
"engineered".** The warm brown dark theme + orange accent + watercolor fox
is a genuinely distinctive identity — most 2026 utilities are grey glass;
this has warmth. What drags it down is density and repetition, not palette.

Specifics:
1. **Dark theme is the star.** The fireside brown is lovely; cards, pills and
   kbd chips are consistent. The cream light theme (onboarding) also holds
   up. No off-brand greys anywhere — good.
2. **Too many competing accent-orange elements per screen.** History: active
   filter pill, Raw badges (one per row!), stats-strip numbers, View details
   link, sidebar active state all shout orange at once. Reserve filled-orange
   for one primary action per view; the per-row "Raw" tab could be outline
   style unless hovered.
3. **Per-row control noise in History.** Every row shows play + copy + kebab
   + info-icon + three version tabs even for a 1-word "Yes." row. Show
   controls on hover (desktop) — instantly calmer.
4. **Typography hierarchy is good** (Inter, tabular numerals in stats), but
   font sizes run small (10–11px labels in sidebar and settings). 2026 desktop
   apps have moved to 13px minimum for secondary text; the sidebar labels
   would breathe at +1px with the reclaimed space from C1.
5. **Stats page is the best screen in the app** — clear hero number, honest
   methodology footnote, fox illustration placed with intent. Use it as the
   quality bar for the rest.
6. **Onboarding is strong** (3 steps, honest "How is this free?", live demo)
   — best-in-class for this category; just fix A4/A6 copy and the
   Raw/Cleaned/Drafted naming (B).
7. **Floater bubble (screenshot 143149)**: white bubble + blue waveform icon
   on the dark desktop reads system-y, not Foxy — bubble could take the cream
   card + orange accent for brand consistency. (Check contrast on light
   wallpapers before committing.)

## F. Code audit (light pass — no refactor urged yet)

Health: **good for its size.** `npm run check` = 0 errors / 12 warnings.
CSP is set properly, keys are keyring-first with DPAPI fallback, no unscoped
fs capabilities — the workspace Tauri-security baseline passes.

Worth fixing:
1. **`Cargo.toml` version 1.4.0** (A1 root cause).
2. **Dead code:** `src/lib/provider-comparison.ts` (unimported),
   `src/lib/ClippyDialog.svelte` (unimported), duplicated sidebar
   markup (C3), unused CSS selectors flagged by svelte-check
   (history `.icon-btn.danger`, `.muted`; onboarding ×2).
3. **`HistoryRow.svelte:18`** — `state_referenced_locally` warning: captures
   initial `rec` value outside a derived; real reactivity smell if rows ever
   update in place (they do — generating cleaned/drafted versions).
4. **A11y warnings:** interactive `<article role="button">`, menu without
   tabindex/keyboard handler in HistoryRow; `autofocus` in onboarding.
   Low-stakes for a desktop app but cheap to fix while touching the files.
5. **Duplicated provider/model change logic** — `changeSttProvider` etc.
   exist nearly identically in `+layout.svelte` and `settings/providers`;
   goes away naturally if C1 removes the sidebar copy (else extract to
   `provider-options.ts`).
6. **`/settings/data` stub route** — either become the real "Data & updates"
   page (C5) or delete.
7. `clippy/+page.svelte` is 3,507 lines — fine per the "tuning knobs at the
   top" convention, but note for any future floater work: extract the quip
   tables and ART table into modules before adding more.
